📋 架构决策总结

决策点 当前选择 理由
AI 能力 Agent 自带 Periplus 只提供数据工具，Agent 自己思考规划。产品化后自建 Agent。
Agent 接入 远程 MCP Server 平台托管，HTTP/SSE 协议，Token 鉴权。数据全托管，隐私由账户控制。
Web 接入 REST API Next.js Route Handlers，与现有代码库无缝衔接。
图片-地图关联 轻量关联 MVP 照片 marker 绑定地图位置，后续深度功能作为 Add-on。
攻略聚合 预置数据 + 后续扩展 早期用预置数据，三层聚合（官方+UGC+外部）后续单独 session 讨论。
交互模式 Agent-Native 混合 Agent 生成规划 → 可视化 UI → 人类反馈 → Agent 迭代优化。

🗺️ MCP 工具列表（暴露给 Agent）

periplus.search_spots
参数: query, location, category, limit
返回: 景点列表（名称、坐标、评分、标签）
periplus.get_spot_detail
参数: spot_id
返回: 景点详情（介绍、开放时间、票价、攻略片段）
periplus.create_route
参数: name, spots[], days, preferences
返回: 路线 ID + 结构化路线数据
periplus.list_my_routes
参数: (无，通过 Token 识别用户)
返回: 当前用户的路线列表
periplus.update_route
参数: route_id, changes（增删改景点、调整顺序）
返回: 更新后的路线
periplus.upload_photo
参数: image_data, route_id?, spot_id?
返回: 照片 URL + 解析出的 GPS 坐标
periplus.rate_spot
参数: spot_id, rating, comment, tags[]
返回: 评分成功确认
periplus.get_guide
参数: destination, topic, days?
返回: 结构化攻略（吃住行游购娱）

🚀 演进路线图

Phase 1: MVP（当前）
• Web 端：地图 + 路线 CRUD + 照片上传（EXIF GPS）+ 轻量关联
• MCP Server：基础工具（search_spots, create_route, list_my_routes）
• 数据：SQLite → 后续迁移 PostgreSQL
• AI：Agent 自带，Periplus 只提供数据
Phase 2: 功能扩展
• 景点评分系统 + 评论
• 攻略预置数据 + 基础查询
• 用户账户体系（OAuth 登录）
• MCP 工具完整化（update_route, upload_photo, rate_spot, get_guide）
Phase 3: 产品化
• 自建 Agent（替代外部 Agent 依赖）
• 攻略聚合（官方+UGC+外部三层）
• 移动端（小程序/App）
• 社交功能（关注、Feed、分享）
• 高级功能：故事模式、版本对比、AI 偏好学习
