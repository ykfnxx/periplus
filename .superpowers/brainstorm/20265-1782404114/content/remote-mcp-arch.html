🔐 鉴权流程：Agent 如何知道"我是谁"

Step 1: 用户在 Periplus 平台生成 MCP Token
登录 Periplus Web → 设置 → MCP 集成 → 生成 Token
periplus_mcp_token_xxxxxxxx
↓
Step 2: 配置 Agent 的 MCP 设置
在 Kimi Code / Codex 的 MCP 配置中添加：
{
  "mcpServers": {
    "periplus": {
      "url": "https://mcp.periplus.travel/sse",
      "headers": {
        "Authorization": "Bearer periplus_mcp_token_xxx"
      }
    }
  }
}
↓
Step 3: Agent 调用工具时自动携带 Token
MCP 协议每次请求都带 Authorization Header
Periplus MCP Server 验证 Token → 识别用户 → 返回该用户的数据

📋 远程 MCP 架构要点

✅ 优势
  • 数据全平台托管，用户无需本地部署
  • 统一账户体系，Web/App/Agent 数据互通
  • 平台控制隐私和权限，可精细化授权
  • 一个 MCP Server，多 Agent 通用
  • 服务端可统一限流、监控、审计
  • AI 能力可平台统一配置（非 BYOA）
⚠️ 挑战
  • 需要维护 MCP Server 服务稳定性
  • 远程调用延迟 vs 本地直调
  • 需要支持 SSE/HTTP 流式传输
  • Token 安全：传输加密 + 定期轮换
  • Agent 侧配置门槛（需手动添加 MCP）
  • 平台需承担 AI 调用成本（非 BYOA）

🤔 关键决策：AI 能力由谁提供？

A

平台统一 AI（推荐）

Periplus 平台配置 AI（OpenAI/Claude/DeepSeek），MCP Server 内部调用。Agent 只负责"意图理解+工具调用"，规划逻辑由平台 AI 完成。平台控制质量，用户无需配置。

B

Agent 自带 AI

Agent（Kimi Code / Codex）自己思考+搜索，Periplus MCP 只提供"数据工具"（查景点、存路线、读照片）。Agent 用自带 AI 做规划，Periplus 只做数据层。

C

混合模式

简单查询（查景点、读路线）走 Agent 自带 AI；复杂规划（多约束路线生成）走平台 AI。Agent 根据任务类型自动选择。
