📋 BYOA 架构要点

✅ 优势
  • 平台零 AI 成本 — 用户自付 Token
  • 天然支持多厂商 — 用户自由切换
  • 利用厂商自带搜索 — 无需自建爬虫
  • 隐私友好 — 用户数据不经过平台 AI
  • 实现极简 — 前端直调或简单转发
⚠️ 挑战
  • 不同厂商输出格式不一致 → 需统一 Schema
  • 厂商搜索能力差异大 → 结果质量不稳定
  • Key 安全 — 浏览器直调暴露风险
  • 无法做用户级 AI 偏好学习
  • 高级功能（多轮、记忆）依赖厂商支持
🔧 关键设计：统一 Schema 层
无论调用哪个厂商，平台定义统一的输入/输出 Schema：

输入 Schema（Prompt 模板）：
{ "intent": "plan_route", "destination": "日本关西", "days": 7, "budget": 10000, "preferences": ["古迹", "美食"], ... }

输出 Schema（AI 必须返回）：
{ "route": { "days": [...], "spots": [...], "transport": [...], "budget_breakdown": {...} } }

每个厂商一个 Adapter，将平台 Schema 转换为厂商特定 Prompt，将厂商输出解析为统一 Schema。

🔐 Key 安全策略选择

A

浏览器直调（最简单）

用户 Key 存在浏览器 localStorage，前端直接调用 AI API。零后端成本，但 Key 完全暴露。

B

后端代理转发（推荐）

用户 Key 加密存数据库，前端请求经后端转发到 AI 厂商。Key 不暴露，后端可做校验/缓存/限流。

C

混合模式

简单查询浏览器直调（快），复杂规划走后端代理（安全）。用户可选。
